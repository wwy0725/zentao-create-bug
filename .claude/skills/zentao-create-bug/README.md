# zentao-create-bug 使用文档

在 Claude Code 里对它说"提个 bug"，它会以专业测试人员视角把你的缺陷描述转成规范的禅道 Bug 单，自动打开禅道表单填写、截图自检、经你确认后提交。

## 工作原理

Claude 通过 playwright MCP 驱动一个独立的 Chrome 浏览器（自带持久 profile，登录一次禅道后长期免登），自动推断四个核心要素并填单：

- **Bug 类型**：按描述推断（APP 问题 / 前端问题 / 服务端问题 / 兼容性 / 需求问题…），选项以禅道页面实际下拉为准
- **标题**：格式 `【迭代日期】【测试轮次】具体现象`，不超过 40 字
- **严重程度**：1（崩溃/数据丢失）～ 4（界面文案小问题），默认 3
- **重现步骤**：严格三段式 `[步骤] / [结果] / [期望]`

提交前会逐字段自检并截图给你确认，点保存后回传 **Bug 链接 + ID + 要素摘要**。

## 环境要求

| 依赖 | 用途 | 缺了会怎样 |
|---|---|---|
| Claude Code | 运行 skill 和 MCP | — |
| Node.js（含 npx） | 拉起 playwright MCP server | `mcp__playwright__*` 工具不出现，MCP 起不来 |
| Google Chrome | 自动化用的就是**本机 Chrome**（不是 playwright 自带浏览器） | 首次打开页面时报浏览器 launch 错误 |
| 禅道可访问 | 内网地址，需在公司内网或 VPN | 页面打不开 |
| Python（可选） | 只有处理**录屏**时用到（本地起 HTTP 服务抽帧） | 纯文字 / 截图提单不需要 |

playwright MCP 包由 `npx` 首次运行自动下载，需要能访问 npm registry（内网机器网络不通时会卡在 server 启动）。

## 安装步骤

1. 拿到整个项目目录（或 clone 仓库）
2. 复制本目录下 `config.example.json` 为同目录 `config.json`，按下表填好必填项
3. 用 Claude Code 打开项目，首次会弹出**信任项目 MCP server** 的提示 → 批准
4. 首次提单：浏览器窗口（有头模式）会自动打开禅道，**手动登录一次**——登录态保存在本机 profile（`~/.claude/playwright-mcp/browser-data`），之后免登；也可以在 config.json 配账密实现自动登录
5. 试一单验证：对 Claude 说 `提个bug：发票列表点查询没反应`

## config.json 字段说明

改完即生效（每次提单都会重读），随时手改。

| 字段 | 必填 | 说明 |
|---|---|---|
| `baseUrl` | ✅ | 禅道地址，如 `https://zentao.dc.servyou-it.com` |
| `productID` | ✅ | 目标产品数值 ID（禅道地址栏里能看到）；**你的账号必须对该产品有提 Bug 权限** |
| `productName` | 建议填 | 产品显示名，仅用于提示 |
| `openedBuild` | ✅ | 影响版本，**每轮迭代都要更新**（如 `代账合规-20261029`） |
| `module` | 选填 | 所属模块路径，`/` 表示根不选 |
| `execution` | 选填 | 所属迭代名称，空 = 不填 |
| `assignedTo` | 选填 | 默认指派人（显示名或账号），空 = 保持页面默认 |
| `story` | 选填 | 相关需求 ID |
| `iterationTag` / `testRound` | ✅ | 标题前缀【迭代日期】【测试轮次】，随迭代更新 |
| `username` / `password` | 选填 | 都填了才会话过期时自动登录；留空则过期时手动登一次 |
| `autoSubmit` | 选填 | `true` = 跳过提交前人工确认直接提交，默认 `false`（建议保持，提交前会截图给你确认） |

## 怎么用

三种输入形态都支持：

- 纯文字：`提个bug：鸿蒙app不支持AI开票里的安全认证`
- 文字 + 截图：截图会**内嵌到重现步骤**里（不是附件），如 `提个bug，截图在 D:\imgs\xxx.png`
- 文字 + 录屏：自动按帧还原操作步骤，录屏作为附件上传，如 `录屏在 D:\rec\xxx.mp4`

一句话里的临时指定永远覆盖配置：`把这个bug提给张三`、`属于xx模块`、`轮次按三`。

## 有头 / 无头切换

默认有头（能看到浏览器窗口，方便手动登录和围观填单）。

切无头：把 `.claude/playwright-mcp/config.json` 里 `browser.launchOptions.headless` 改为 `true`，然后重启 MCP（杀掉 MCP 的 node 进程让 IDE 重拉，或重启会话）；切回有头改 `false` 同理。

⚠️ 无头模式下浏览器窗口不可见，"手动登录一次"流程走不通——无头 + 未配账密 + 会话过期时，先切回有头登录。

## 常见问题

| 现象 | 原因与处理 |
|---|---|
| `mcp__playwright__*` 工具不存在 | Node/npx 没装（`node -v` 验一下），或首次拉包网络不通；修好重启会话 |
| 打开页面报浏览器 launch 错误 | 本机没装 Google Chrome，装一个 |
| 弹窗"您无权访问该产品" | config.json 的 `productID` 换成你有权限的产品 |
| 页面跳到登录页 | 会话过期：配了账密会自动登录；没配就在浏览器窗口手动登一次 |
| 录屏读不出来 | 仅支持 H.264 编码的 mp4（Windows 自带录屏就是）；HEVC 不支持 |
| 录屏超 50M | 超过禅道附件上限，不会上传附件，但 bug 照常提交并明确告知你 |
| 提交时红字提示缺必填项 | 会把提示原文报给你，补齐后重新自检再提交，不会编造内容凑必填 |

## 边界

- 本 skill 只管"创建 Bug"：改 Bug 状态、查 Bug 等不在范围内
- 信息不足时（判断不出操作路径、期望行为）会先问你，不编造业务细节
- 提单过程中产生的临时文件（上传副本、抽帧图片）提交完成后自动清理
